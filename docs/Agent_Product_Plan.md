## 一、产品定位

一个**桌面自动化 Agent（智能体）**：既能用**主模型**完成核心任务，又能在任务包含子任务时，**自动把子任务分配给最专业、最高性价比的模型**，并让使用者全程可视化、可配置地掌握整个过程。

一句话：**「一个大脑总指挥 + 一群专业执行者，按性价比自动分工」的执行助手。**

---

## 二、核心价值

| 价值 | 说明 |
| --- | --- |
| 专业化 | 不要求单个模型「全都会」，而是把任务拆给各自擅长的模型 |
| 高性价比 | 简单任务不浪费昂贵模型，复杂任务才动用强模型，控制成本 |
| 可掌控 | 分配过程可视化、规则可配置，不是黑盒 |
| 本地安全 | 敏感任务可强制留在本地模型，不外发 |

---

## 三、目标用户与场景

- **目标用户**：需要处理多类型/较大任务、希望用「本地 + 云端」多模型协同的个人或团队。
- **典型场景（MVP 演示示例）**：
  1. 生成一份结构化报告 → 拆分「目录规划 / 撰写各章节 / 校对润色」等子任务，分配给不同模型。
  2. 代码审查 → 主模型总览，代码细节子任务分给代码专长模型。
  3. 多语言翻译 → 不同语言子任务分配给对应擅长的模型。

---

## 四、MVP 功能范围（做 / 不做）

### MVP 包含
1. 主模型任务执行（默认本地 Ollama，`qwen2.5:14b`）。
2. 子任务识别与拆分。
3. **混合分配器**：以 LLM 路由为主、人工规则覆盖为辅。
4. 多模型调用：本地 Ollama + 云端 OpenAI 兼容 API。
5. 桌面界面：任务输入、分配结果、执行进度、模型管理。
6. 模型增删改配置（名称、来源、擅长领域、成本、能力分）。

### MVP 不包含（后续迭代）
- 插件生态、自学习调优、任务持久化队列、多用户与权限。
- Agent 记忆、复杂工具链、可视化流程图编排。

## 五、整体架构（概念层）

```
┌───────────────────────────────┐
│        桌面界面（GUI）          │
│  任务输入 · 进度 · 结果 · 配置  │
└──────────────┬────────────────┘
               │
┌──────────────▼────────────────┐
│       编排核心（自研轻量核）     │
│                               │
│  主执行器 ──► 混合分配器        │
│                │ LLM路由       │
│                │ 规则覆盖       │
│                ▼               │
│            模型管理器（记分）    │
└──────────────┬────────────────┘
               │ 按类型分发
   ┌───────────┼───────────┐
   ▼           ▼           ▼
 本地模型    云端模型    备用模型
(Ollama)  (API兼容)   (可扩展)
```

**三个核心概念：**
- **主执行器**：跑主任务，识别可拆分子任务。
- **混合分配器**：决定「哪个子任务 → 哪个模型」，规则优先。
- **模型管理器**：登记模型能力/成本，输出「性价比分」。

---

## 六、任务分配策略（混合）

1. **LLM 路由**：路由模型输出结构化结果（子任务、所需技能、建议模型）。
2. **性价比评分**：`性价比分 = f(能力分, 成本)`，选最高者。
3. **规则覆盖**（优先于 LLM）：
   - 本地离线 → 自动切云端；
   - 敏感任务 → 强制本地；
   - 用户手动指定某类型 → 固定模型。
4. **回退**：首选失败，按评分依次回退，保证完成。

## 十、风险与注意事项

- 本地 Ollama 需先启动服务，否则默认回退云端。
- 云端 API 需使用者提供 Key（记录于 `credentials.md`，**绝不提交 GitHub**）。
- 拆分子任务质量依赖路由模型，需在 M1 验证提示词与拆分粒度。
