## 摘要

本文档定义「Agent 自动化智能体」正式版本的产品与技术设计。基于已跑通的 demo
（主模型 + 混合分配 + PySide6 界面），将设计扩展为**可配置、可扩展、健壮、可打包**的正式桌面应用。

核心设计思想不变：**「一个大脑总指挥 + 一群专业执行者，按性价比自动分工」。**

---

## 1. 产品目标与范围

### 1.1 目标
1. 以单一主模型完成主任务。
2. 自动把可拆分子任务分配给**最专业 + 最高性价比**的模型执行。
3. 提供**可视化、可配置**的桌面应用，让使用者掌控分配过程。
4. 支持本地（Ollama）与云端（OpenAI 兼容）双模型源，敏感任务可强制本地。

### 1.2 正式版范围
**包含：**
- 完整编排核（任务队列、异步执行、失败回退与重试、超时控制）。
- 可配置模型管理（增删改、来源、技能、成本、能力分、主/备用标记）。
- 混合分配器（LLM 路由 + 人工规则覆盖），规则表可视化编辑。
- 桌面界面完善（任务输入/历史、进度与分配可视化、结果预览、异常提示）。
- 配置持久化（JSON/INI，敏感项外置于 `credentials`）。
- 打包分发（PyInstaller 生成 exe）。

**不包含（后续迭代）：**
- 插件生态、Agent 记忆 / 工具链、多用户与权限、云端任务队列。

## 3. 系统架构（正式版）

```
┌────────────────────────────────────────────────────────┐
│                     桌面层 (Desktop)                    │
│  PySide6 · 任务输入/历史 · 进度与分配可视化 · 结果预览    │
│  模型配置页(分类式) · 规则配置 · 设置 · 异常与日志视图    │
└──────────────────────┬─────────────────────────────────┘
                       │ 命令/事件
┌──────────────────────▼─────────────────────────────────┐
│                   编排核心 (Core)                       │
│  ┌──────────────┐  ┌───────────────────────────────┐   │
│  │  TaskQueue    │  │  Orchestrator(主执行编排)     │   │
│  │ 任务调度/状态  │──▶│ 运行时:[拆分→分配→执行→汇总] │   │
│  └──────────────┘  │  Transitions / 超时/重试       │   │
│                    │  Callback → 界面进度            │   │
│                    └──────────────┬────────────────┘   │
│                    ┌──────────────▼───────────────┐    │
│                    │  Router(混合分配器)           │    │
│                    │  LLM路由 → 规则覆盖 → 评分   │    │
│                    │  回退 / 锁定 / 敏感性约束    │    │
│                    └──────────────┬───────────────┘    │
│                    ┌──────────────▼───────────────┐    │
│                    │  ModelManager(模型/评分)     │    │
│                    │  注册·技能·成本·能力·主备用   │    │
│                    └──────────────┬───────────────┘    │
├───────────────────────────────────┼────────────────────┤
│   Provider 层(统一 BaseProvider)   │                    │
│  OllamaProvider · OpenAIProvider · MockProvider       │
└───────────────────────────────────┼────────────────────┘
                                    │
                    ┌───────────────┼──────────────┐
                    ▼               ▼              ▼
              本地Ollama     云端OpenAI兼容     预留扩展(多来源)
```

**分层依赖（自下而上）：**
`Provider`（模型调用）→ `ModelManager`（模型信息）→ `Router`（分配决策）
→ `Orchestrator`（执行编排）→ `TaskQueue`（任务调度）→ `Desktop`（界面）。

## 4. 核心模块详细设计

### 4.1 Provider 层（统一模型调用）
- 抽象基类 `BaseProvider.generate(prompt) -> str`、`chat_json(prompt)`。
- 三个实现：`OllamaProvider`（本机 REST）、`OpenAIProvider`（OpenAI 兼容）、`MockProvider`（离线/演示）。
- **超时与中断**：每次调用带可配超时（默认 120s）；支持取消令牌以便用户中止。
- Provider 由 `ModelManager` 依据模型来源动态构建，避免硬编码。

### 4.2 ModelManager（模型注册与评分）
- 数据：`ModelInfo{key,name,source,endpoint,skills,cost,capability,is_primary,api_key_ref}`。
- `register / get / all / update / remove / set_primary`。
- 评分：`score = W_cap·能力·专业匹配 + W_cost·成本加成`，权重可配置。
- 主模型标记：全局唯一主模型，缺失时提示并可使用备用。

### 4.3 Router（混合分配器）
决策顺序（高→低）：
1. **规则覆盖**（人工规则优先）：敏感 → 强制本地；本地离线 → 切云端；类型锁定 → 固定模型。
2. **LLM 路由**：路由模型输出 `[子任务→技能]` 结构化 JSON。
3. **性价比选择**：按技能经 ModelManager 取最高分模型。
4. **回退**：首选失败 → 排除后取次优 → 全部失败则标记失败并上报。
5. 敏感关键词库可配置；规则表支持可视化编辑并持久化。

### 4.4 Orchestrator（主执行编排）
- 输入主任务 → 产出：
  1. 主模型总览回复（失败降级提示）。
  2. 子任务解析（LLM / 规则）。
  3. 分配（Router）。
  4. 逐个子任务执行（Provider），失败触发回退。
  5. 汇总结果。
- 执行在**后台线程**；通过回调/信号把进度推给界面（不阻塞 UI）。
- 支持**中止**：用户取消后中断当前子任务链。

### 4.5 TaskQueue（任务调度）
- 正式版支持**顺序队列**：可连续提交多个主任务，逐个执行。
- 任务状态机：`pending → running → done / failed / canceled`。
- 保存任务历史（时间、输入、分配、结果、耗时）。

## 5. 桌面界面设计（正式版）

采用**分类式布局**（符合使用者偏好：层级分类 + 单行文本 + 图标）：

| 区域 | 内容 |
| --- | --- |
| 主工作台 | 主任务输入、运行/中止按钮、进度条、当前状态提示 |
| 分配视图 | 表格：子任务 → 模型 → 理由/评分/状态，失败高亮并显示回退 |
| 模型管理页 | 分类卡片：本地 / 云端；新增/编辑/删除/设为主模型；字段与评分预览 |
| 规则配置页 | 敏感关键词、离线/锁定规则的可视化编辑 |
| 任务历史 | 历史列表 + 单条详情回看 |
| 设置页 | 默认主模型、Ollama 地址、云端口、超时、打包相关信息 |
| 日志/异常视图 | 运行时日志与错误详情，便于排障 |

> 界面配色与交互沿用 demo；正式版增加工具栏、状态栏（模型/服务在线状态）。

## 6. 数据与配置设计

- **配置**：`config.yaml`（或 JSON）——模型表、规则表、权重、服务地址、超时。
- **敏感项**：云端 API Key 等存于 `credentials.json`（`.gitignore` 排除，绝不提交）；界面提供「从文件引用 / 环境变量 / 加密存储」接入方式。
- **历史**：`tasks_history.json`（本地），可清空。
- **日志**：`logs/`（级别可配），异常详情写入。

---

## 7. 健壮性设计

- 所有网络调用：超时、错误分类（网络 / 认证 / 模型缺失 / 超时）。
- 所有 UI 操作不阻塞主线程（QThread / QTimer / 信号槽）。
- 失败分级处理：可回退的降级，不可恢复的明确报错并写入日志。
- 应用级全局异常兜底（避免静默崩溃）。

---

## 8. 打包与运行

- 依赖管理：`requirements.txt` + 项目内 `.venv`。
- 打包：PyInstaller 单文件 exe；打包后仍支持外部 Ollama 与云端配置。
- 运行入口：`python -m agent_app.main`（开发）/ 打包 exe（发布）。

## 10. 风险与决策点

| 风险/决策 | 说明 | 建议 |
| --- | --- | --- |
| 云端 API Key 管理 | 正式版需安全存放 | credentials 文件/gitignore + 加密 |
| 主模型不可用 | Ollama 缺模型或离线 | 自动回退 + 明显提示 + 配置向导 |
| 评分权重选择 | 影响分配结果 | 保留配置项，默认能力优先兼顾成本 |
| 打包体积 | PySide6 较大 | 单文件打包，接受体积 |
| 是否需要插件化 | 后续迭代 | 正式版预留扩展点即可 |
